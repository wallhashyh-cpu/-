مشروع Node.js للنشر على Railway.

R21.36 — التعديل رقم 2:
- عرض نسخة كتالوج محلية موثقة سابقاً من Firebase بسرعة عند توفرها، مع تحديث Firebase بالخلفية.
- تبسيط مركز المطورين وشرح رابط API ومفتاح المستخدم وطرق المصادقة والمسارات الفعلية.
- استبدال زر واتساب العائم بقائمة (+) تشمل واتساب وتيليجرام وYouTube وGoogle Play وطلب الخدمة وشحن الرصيد.
- إضافة تصفير إحصائيات الموقع عبر نقطة زمنية موثقة في Firebase دون حذف الطلبات أو الأرصدة أو سجلات المعاملات الأصلية.

أوامر التشغيل:
- البناء والفحص: npm run build
- الاختبارات الكاملة: npm run test:full
- التشغيل: npm start

إعدادات Railway:
- Builder: RAILPACK
- Build: npm run build
- Start: npm start
- Health check: /healthz
- Node المطلوب: >=22.23.0 <23

أهم إصلاحات R21.17 وR21.18 وR21.21 وR21.24:
- الحفاظ على نسبة الربح الخاصة بكل خدمة عند تحديث تكلفة المزود.
- النسبة العامة تطبق فقط على الخدمات التي تم ضبطها على النمط العام أو لا تملك نسبة خاصة.
- لا يُنشر سعر جديد في الكاش المحلي ولا يُقبل الطلب بعد إعادة التسعير حتى يؤكد Firebase حفظ الحقول الجديدة.
- تحديثات المزود تقارن القيم في Firebase قبل الكتابة حتى لا تستبدل تعديلاً إدارياً أحدث.
- اختبار محاكاة فشل Firebase يثبت بقاء السعر المحلي والبعيد السابقين عند فشل الحفظ.

تتضمن الحزمة أيضاً إصلاحات R21.15 وما قبلها المتعلقة بسجل حذف الأقسام، عدم عودة المحذوف بعد الاسترجاع، إزالة تكرار أسماء الأقسام، ربط أقسام العميل، إدارة الأقسام حسب المنصة، شعار صدى العراق المحلي، تفاصيل الطلبات، ونظام الاستخدام المجاني المشترك مرتين لكل حساب خلال 24 ساعة.

راجع RELEASE_REPORT_AR.md للتفاصيل وDEPLOY_R40_AR.md للنشر والتحقق.

تنبيه: لا تتضمن الحزمة بيانات المستخدمين أو الطلبات أو الأرصدة المحلية داخل مجلد البيانات؛ لا تستبدل Railway Volume ولا تغيّر إعدادات Firebase أو SESSION_SECRET أو مفاتيح المزودين عند النشر. خذ نسخة احتياطية أولاً.

حدود التحقق: الاختبارات محلية وبقاعدة Firebase اصطناعية؛ لم يتم الاتصال بFirebase الإنتاجية أو Railway أو مزود SMM حقيقي. بيئة الفحص الفعلية لهذه الحزمة موثقة في سجل الاختبارات؛ المطلوب للنشر Node.js 22.23.0 أو أحدث ضمن الإصدار 22. لا يوجد package-lock.json بالمصدر، ويلزم إنشاءه في بيئة متصلة بسجل npm لضمان تثبيت قابل للتكرار. لا ترفع إلى المستخدمين قبل اختبار قبول تجريبي على نسخة Firebase منفصلة.


R21.21: تنظيف أقسام metadata اليتيمة وربط فهرس الأقسام بسجل الحذف الدائم؛ لا يبقى القسم الفارغ إلا عند تفعيل المدير خيار الاحتفاظ به صراحةً، وعلامات الأقسام القديمة وحدها لا تكفي. الخدمات المجانية أصبحت مجمعة حسب المنصة والقسم، مع نقل أو إيقاف/تفعيل أو حذف المجموعة.

R21.21: معالج جديد للخدمات المجانية يبدأ بإنشاء قسم واختيار منصة أو أكثر، ثم استرداد خدمات المزود أو التحقق من Service ID، وضبط حدود موحدة أو فردية، وإضافتها مجاناً مع حد محاولتين لكل حساب كل 24 ساعة. متوسط وقت المزود يُنقل فقط عند توفره من API ويُعرض للعميل دون قيمة زمنية مصطنعة.

R21.24: إعادة تصميم إدارة الخدمات المجانية كمسار يبدأ بإنشاء قسم واختيار منصة/منصات، ثم استرداد خدمات المزود متعددة أو التحقق اليدوي من Service ID، وضبط الحدود الموحدة أو الفردية، مع إبقاء سعر العميل صفراً والحصة المشتركة محاولتين لكل حساب خلال 24 ساعة. وقت المزود يُحفظ ويُعرض فقط عندما يرد فعليًا من API.

R21.24: أقسام الخدمات المجانية تبقى ظاهرة وهي فارغة حتى الحذف اليدوي، مع فرز تكلفة المزود من الأقل إلى الأعلى. حذف الخدمة أو القسم يزيل البيانات والمراجع من Firebase ويضيف علامات تمنع استعادة الخدمات المجانية المحذوفة. بطاقات طلباتي تعرض بيانات الطلب الحقيقية وشعار المنصة محليًا، وزر إعادة الطلب يجهز النموذج ولا يرسله تلقائيًا.

R21.24: إضافة تبويب «الأكثر مبيعاً» في لوحة إدارة الخدمات مع زر إظهار/إخفاء واختيار عدة منصات، وحفظ الإعدادات في Firebase بعد التحقق. يعرض القسم الخدمات التي لها طلبات حقيقية فقط، مرتبة بحسب عدد الطلبات المسجل فعليًا، مع استبعاد سجلات الاختبار والمسودات والبيانات التاريخية للقراءة فقط. تتم مطابقة الطلبات بمعرف خدمة الموقع أولاً ثم معرف المزود المركب عند الحاجة، وتُحترم عضوية المنصة الصريحة. شرط Node للنشر >=22.23.0 و<23.

R21.26: إدارة الأقسام حسب المنصة المختارة فقط؛ نقل قسم إلى منصة واحدة؛ إزالة القسم من منصة محددة مع إبقائه في المنصات الأخرى؛ حذف بقسم بتأكيد واحد دون كتابة الاسم؛ حفظ الأقسام الفارغة افتراضيًا؛ إصلاح ظهور خدمات عروض صدى العراق حسب عضوية القسم؛ وتحديث فوري لقائمة الأكثر مبيعاً بعد تأكيد الحفظ من Firebase.
R21.25: إصلاح فشل حفظ دفعات خدمات المزود الكبيرة عندما تتضمن أسماء الأقسام شرطة مائلة أو رموزاً خاصة. لم يكن 1,208 حداً أقصى؛ السبب كان استخدام اسم القسم الخام كمفتاح JSON داخل pinnedPositions. أصبحت مفاتيح التثبيت والترتيب تُحوّل إلى مفاتيح Firebase آمنة، مع الحفاظ على اسم العرض الأصلي، وتنظيف مفاتيح التثبيت القديمة، وفحص كل كائن JSON قبل إرساله إلى Firebase. إعادة استيراد نفس الخدمات آمنة لأنها تُطابق بمعرّف المزود ومعرّف خدمته ولا تنشئ تكراراً.

R21.27: إصلاح وجهة استيراد خدمات المزود. منصة حفظ الخدمات أصبحت اختيارًا إلزاميًا بلا وجهة افتراضية؛ فلتر منصة المصدر اختياري ومستقل. الخادم والواجهة يحفظان الخدمات والأقسام وcategoryMeta وترتيب الأقسام على المنصة المختارة فقط، ويزيلان عضويات المنصات القديمة، ويتجاوزان علامات عروض صدى العراق القديمة عند وجود وجهة صريحة. «عروض صدى العراق» منصة مستقلة وليست «الكل».


R21.35: إصلاح سبب ظهور الأقسام فارغة من الخدمات في صفحة الطلب. محرك العرض كان يمرر الصفوف عبر مفتاح رسم مؤقت، ثم يطلب خطأً أن يكون المفتاح جزءًا من groups/categories؛ هذا الشرط كان يسقط كل الخدمات. أصبح يقبل الصفوف المحضّرة داخل مفاتيح الرسم الداخلية فقط، مع الإبقاء على فحص المنصة الفعلية وفحوص عضوية الأقسام الحقيقية. أضيف اختبار تشغيل يغطي إنستغرام وتيك توك والأقسام الحقيقية.
