صدى العراق — الإصدار 3.2 / R20.30

حزمة إصلاح موحدة لكتالوج Firebase، عروض صدى العراق، أسماء الأقسام العربية، نافذة حسابي وتفاصيل الطلبات.

أبرز تغييرات R20.29:
- إبقاء «الكل» أول منصة في شريط اختيار المنصة، و«عروض صدى العراق» بجانبها كمنصة مستقلة.
- عند فتح «الكل»، تظهر مجموعة «عروض صدى العراق» في بداية قائمة الفئات، ثم بقية الأقسام العادية.
- استخدام نطاق حفظ مستقل لعروض صدى العراق (sadairaq)، مع الاحتفاظ بـ all كعرض جامع فقط.
- منع تصنيف خدمات Instagram وTikTok وغيرها كعروض بسبب علامات تجميع قديمة مثل platformScope=all أو showInAll.
- إخفاء اسم الحاوية القديمة «أقسام عامة - منصة الكل» من قائمة العرض ودمج خدماتها/الأقسام الفعلية في مجموعة العروض، دون حذف سجلات Firebase القديمة.
- فك أسماء الأقسام المشفرة URI/UTF-8، وإزالة المعرّفات الداخلية من النصوص المعروضة، مع استخدام اسم المفتاح العربي كبديل عند فساد الاسم المخزن.
- إعادة محاولة تحميل الكتالوج عند القراءة الفارغة غير المؤكدة أو فشل Firebase، بحيث تظهر الخدمات عند توافر قاعدة البيانات دون إضافة قسم/خدمة يدوياً.
- عدم رفع كاش Railway فوق Firebase إلا إذا كان كاشاً موثقاً بسجل تحقق سابق.
- ضبط نافذة «حسابي» على ارتفاع المحتوى بدلاً من ترك فراغ كبير أسفلها.
- نافذة تفاصيل الطلب للعميل في وسط الشاشة، مختصرة وبدون رابط الهدف الطويل: رقم صدى العراق، رقم المزود، الخدمة، الكمية، السعر، الحالة، وبيانات قبل/بعد عند توفرها.
- الحفاظ على نافذة تفاصيل الإدارة وأدواتها الأصلية.
- الحفاظ على صفحة إنشاء الطلب بالشكل اليدوي السابق: لا حركة منصات تلقائية ولا بطاقة خطوات كبيرة.
- الاحتفاظ بشعار صدى العراق ضمن أصول المنصة ومكتبة صور الأقسام.


إضافات R20.30 (إصلاحات الصور والأقسام والإشعارات):
- فك ترميز أسماء الأقسام التي تظهر كمفاتيح تقنية/نصوص URL مشفرة وتحويلها إلى العربية المقروءة.
- إصلاح أولوية صور الخدمات لقبول مسارات الأصول المحلية، كي يظهر شعار التطبيق على بطاقة الخدمة حتى داخل أقسام «عروض صدى العراق».
- إعادة تنظيم «الأقسام والصور» لتبدأ باختيار المنصة ثم البحث، وإصلاح حفظ صورة SadaIraq وإعادة تسمية القسم وروابط خدماته مع تحقق Firebase.
- تصميم جديد لقسم الإشعارات، ونقل تفعيل إشعارات الهاتف إلى داخله، وإعادة محاولة الطلب بعد تجديد جلسة المستخدم عند 401.
- إضافة اختبار انحدار مخصص لهذه الإصلاحات ضمن npm test.

أوامر Railway:
- Build: npm run build
- Start: npm start
- Health check: /healthz
- Node: >=22.23.5 <23

الاختبارات:
- npm test

اقرأ DEPLOY_R20.30_AR.md وTEST_RESULTS_R20.30_AR.md قبل النشر. لا تحذف Railway Volume، ولا تغيّر SADA_DATA_DIR أو إعدادات Firebase أثناء التحديث.

حدود التحقق:
نجحت الاختبارات المحلية وعلى Firebase تجريبية فقط. لم يتم النشر على Railway الإنتاجي ولم تُكتب بيانات في Firebase الحقيقية. إذا كانت الخدمات محذوفة فعلياً من Firebase ولا توجد في كاش موثوق أو نسخة احتياطية، لا يمكن للكود إعادة إنشاء السجلات القديمة من تلقاء نفسه.
